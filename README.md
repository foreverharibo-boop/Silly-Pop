# Silly-Pop (실리팝)

Termux 서버가 AI 응답을 다 받으면 **같은 휴대폰의 Android 앱**으로 알림을 보내는 확장입니다.
웹 확장 1.5.0 · 서버 플러그인 2.3.1 · Android 앱 0.2.6.

SillyTavern/SillyTavern-PushNotifications(Cohee1207)의 포크이며, 모바일·Android 연동은 담은이 추가했습니다.
라이선스: AGPL-3.0-or-later.

## 앱 0.2.6

- 선택한 날렵한 S와 작은 별 로고를 런처·앱 화면·알림 이미지에 적용합니다.
- 앱 하단 버전은 실제 APK 버전에서 자동으로 표시합니다.
- 블랙·화이트 설정은 홈 화면 아이콘, 앱 테마와 알림 본문 이미지에 적용됩니다. 삼성 간략한 팝업이 별도로 불러오는 앱 기본 아이콘에는 자동 연동되지 않습니다. 앱 기본 아이콘은 블랙입니다.
- 알림 감지·전송은 바뀌지 않습니다. 웹 확장 1.5.0 / 서버 2.3.1을 그대로 사용합니다.

## 서버 2.3.1 / 앱 0.2.5

- 알림 본문을 “AI 응답이 도착했어요.”로 간단히 표시합니다.
- 앱의 블랙·화이트 선택을 알림 본문의 ST 이미지에도 적용하며, 기존 알림은 다시 울리지 않고 색상을 갱신합니다.
- 시스템 상태 표시줄의 작은 단색 아이콘과 알림 배치는 Android/제조사 설정을 따릅니다.
- 서버 플러그인을 업데이트하고 서버를 재시작하세요. 앱은 0.2.5를 덮어 설치합니다. 웹 확장 1.5.0은 그대로 사용합니다.

## 확장 1.5.0 / 서버 2.3.0 / 앱 0.2.4

- 알림 기준을 **Termux 서버의 AI 응답 수신 완료**로 변경했습니다. 100LOG/inSTead 요청에도 전송 전에 표시를 붙이고 서버에서 알림을 보냅니다. 브라우저가 완료·표시 코드를 실행할 때까지 기다리지 않습니다.
- 100LOG 초안과 재작성, inSTead 재작성은 확인된 함수 호출 경로로 구분합니다. 호출 경로가 바뀌어 식별하지 못하면 제외됩니다. 일반 quiet 수집·번역·검수 보조 요청과 사용자 대필은 제외합니다.
- 100LOG는 **검수 완료 전에도 알림이 올 수 있고**, 이후 재작성 응답이 도착하면 다시 알립니다. 이는 최종 검수 통과 알림이 아닌 서버 응답 알림입니다.
- 화면 게시 알림은 종료했습니다. 실리로 돌아와 답변을 표시해도 추가 알림을 보내지 않습니다.
- 앱이 알림 클릭으로 삼성 인터넷을 강제로 열던 동작을 제거했습니다. Android에서 해당 URL을 처리하는 설치된 WebAPK가 하나 확인되면 그 웹앱을 열고, 없거나 모호하면 아무 화면도 열지 않습니다. 홈 화면 바로가기처럼 별도 WebAPK가 없는 설치 방식은 자동으로 열 수 없습니다.
- 웹 확장·서버 플러그인을 업데이트하고 서버를 재시작한 뒤 페이지를 새로고침하세요. 클릭 동작 변경은 앱 0.2.4 덮어 설치가 필요합니다.

아래는 이전 버전 기록입니다. 1.4.5~1.4.7의 화면 게시 기반 알림은 1.5.0에서 더 이상 사용하지 않습니다.

## 확장 1.4.7 실리태번 표시 후 완료 정보 읽기 수정

- 실리태번은 답변을 표시할 때 `message.extra`를 `swipe_info[n].extra`에 복사합니다. 이 상태에서 100LOG 표시는 찾으면서도 완료 번호를 바깥의 `swipe_info[n].gen_id`에서만 읽어 알림을 누락하던 오류를 수정했습니다.
- 안쪽 `extra.gen_id`와 기존 100LOG 스와이프 형식을 모두 처리합니다.
- 실제 실리태번의 `ensureSwipes`·`syncMesToSwipe` 함수로 변환 결과를 확인하고, 화면 표시 후 데이터 구조의 누락·중복 방지 회귀 테스트를 추가했습니다.
- 확장만 업데이트하고 실리태번 페이지를 새로고침하세요. 서버 2.2.5와 앱 0.2.3은 그대로 사용합니다.

## 확장 1.4.6 최종 답변 감지 보완

- 100LOG의 새 답변 게시 이벤트와 완료 시각으로 직접 알림을 감지합니다. 앞선 quiet 생성 시작 이벤트가 없거나 다른 생성으로 초기화돼도 게시된 답변을 처리합니다.
- 이미 보던 답변, 과거 스와이프, 채팅 열기·새로고침, 같은 답변의 중복 표시를 제외합니다.
- 확장만 업데이트하고 실리태번 페이지를 새로고침하세요. 서버 2.2.5와 앱 0.2.3은 그대로 사용합니다.
- 기존 1.4.5 호환 경로는 유지하며 브라우저가 최종 답변을 게시해야 한다는 조건은 동일합니다.

## 확장 1.4.5 / 서버 2.2.5 검수·재작성 답변 알림

- 100LOG가 quiet로 초안·검수를 마친 뒤 채팅에 게시한 새 답변과 스와이프에 알림을 보냅니다.
- inSTead(통제광)의 재작성 완료 후 저장·새로 표시된 스와이프도 감지합니다.
- quiet 요청 자체에는 알림을 보내지 않습니다. 검수 중간 결과·실패·취소·기존 답변 다시 보기에는 알림을 보내지 않으며 중복 표시도 한 번만 처리합니다.
- 대화 본문이나 피드백은 알림 서버로 전송하지 않습니다. 기존 알림 켜기·백그라운드 조건을 그대로 적용합니다.
- 이 경로는 확장이 **최종 답변을 게시하는 시점**에 작동합니다. 브라우저가 완전히 정지해 검수·게시 코드 자체가 실행되지 않으면 해당 코드가 재개될 때까지 기다립니다.

확장과 서버 플러그인을 모두 업데이트하고 Termux 서버를 재시작한 뒤 실리태번 페이지를 새로고침하세요. Android 앱은 0.2.3 그대로 사용합니다.

## 확장 1.4.4 / 서버 2.2.4 자동 알림 진단

- 휴대폰의 연결 확인 버튼에서 요청 감시·생성 이벤트·실제 전송 기록을 확인할 수 있습니다.
- AI 요청이나 Android 알림을 발생시키지 않는 별도 검사로 헤더·본문 전달과 서버 응답 감지를 확인합니다. 실제 생성 API 전체의 성공을 보장하는 검사는 아닙니다.
- 서버 전체의 미표시 요청을 이 탭의 최근 답변처럼 보여 주던 오해 소지가 있는 표시를 수정했습니다. OPTIONS 등 생성 POST가 아닌 요청은 제외합니다.
- 최근 8개 상태만 메모리에 기록합니다. 대화·프롬프트·키는 진단에 포함하지 않으며 새로고침하면 초기화합니다.
- 이 버전 당시 inSTead의 quiet 재작성은 제외됐습니다. 최종 게시 감지는 1.4.5에서 추가됐습니다.

Android 앱은 0.2.3 그대로 사용합니다. 확장과 서버 플러그인을 업데이트하고 서버를 재시작한 뒤 **휴대폰 실리태번에서 연결 확인**을 누르세요.

## 확장 1.4.3 / 서버 2.2.3 요청 표시 누락 수정

- 생성 이벤트를 건너뛰거나 본문에서 알림 표시가 빠진 경우를 실제 fetch 전송 지점에서 보완
- 같은 출처의 알려진 생성 API에만 별도 알림 헤더 전달; 서버는 헤더와 기존 본문 표시 모두 지원
- 프롬프트·생성 옵션·인증/CSRF 헤더·취소 신호·응답 스트림 유지, 추가 AI 호출 없음
- 숨은 생성(quiet)·사용자 대필(impersonate)·관련 없는 요청 제외
- 이벤트 표시 없이 들어오는 실제 HTTP 생성 요청의 자동 알림 통합 테스트 추가

Android 앱은 0.2.3 그대로 사용합니다. 확장과 서버 플러그인을 모두 업데이트해야 합니다.

## 확장 1.4.2 / 서버 2.2.2 자동 알림 수정

- 늦게 도착한 과거 화면 상태가 최신 백그라운드 상태를 덮어쓰지 않도록 처리
- blur·pagehide·freeze에서 명시적으로 백그라운드 상태 전달
- 연결 확인 대기 중이거나 생성 시작 이벤트를 거치지 않은 명시적 메인 요청에도 알림 표시 부착
- 생성 요청보다 오래된 화면 상태 대신 요청 당시 상태를 사용
- 연결 확인 시 최근 자동 알림의 전송·생략·실패 이유 표시 (대화 본문·API 키 저장 없음)
- 실제 HTTP/SSE 응답 완료와 브라우저 상태 순서 역전을 포함한 자동 알림 통합 테스트 추가

Android 앱은 0.2.3 그대로 사용하며, 이번 수정은 APK 재설치가 필요 없습니다.

## 설치·업데이트

### Android 앱

[APK 다운로드](https://github.com/foreverharibo-boop/Silly-Pop/releases/tag/v0.2.6-test)

0.2.1부터 고정 서명을 사용합니다. **0.2.1 이상 → 0.2.6는 삭제하지 않고 덮어 설치**합니다.
0.2.0 이하는 서명이 달라 기존 앱을 한 번 삭제해야 하며 앱 설정이 초기화됩니다.
설치 후 앱을 한 번 열어 알림 권한을 허용하고 테스트 알림을 눌러 주세요.

### 웹 확장

실리태번 확장 관리에서 아래 저장소를 설치하거나 업데이트하고 새로고침하세요.

```text
https://github.com/foreverharibo-boop/Silly-Pop
```

### 서버 플러그인 (웹 확장과 별도로 업데이트해야 합니다)

같은 휴대폰의 Termux에서 실행합니다. Termux:API 앱은 필요하지 않습니다.

```bash
pkg install termux-am
cd ~/SillyTavern
node plugins.js install https://github.com/foreverharibo-boop/Silly-Pop
```

이미 기본 경로에 설치했다면:

```bash
git -C ~/SillyTavern/plugins/Silly-Pop pull --ff-only
```

설치 폴더를 직접 바꿨다면 해당 폴더 경로를 사용하세요.
config.yaml의 enableServerPlugins: true가 필요합니다.
업데이트 뒤 **실리태번 서버 프로세스를 완전히 종료하고 다시 시작**하세요.
확장 설정 아래에 **확장 1.5.0 · 서버 2.3.0**가 표시되는지 확인한 뒤 연결 확인과 테스트 알림을 누르세요.

Android 14 이상에서는 **전송 준비됨 · 앱 자동 확인 미지원**이 정상적으로 표시될 수 있습니다.
이 표시는 설치/권한/수신 성공을 확정하지 않습니다. 앱을 열어 알림 권한을 확인한 뒤 테스트 알림이 실제로 뜨는지 확인하세요.

## 연결 문제

- 테스트 알림은 오지만 자동 알림이 없으면 답변 완료 후 연결 확인을 눌러 **최근 답변**의 처리 결과를 확인하세요. 이 기록은 서버 메모리에만 유지됩니다.
- '다른 앱을 볼 때만'을 켜면 실리태번을 보고 있는 동안은 생략합니다. 홈 화면이나 Termux로 전환했다면 알림 대상입니다.
- 앱 안의 알림 허용은 서버 연결 성공을 의미하지 않습니다.
- 서버 버전이 예전이면 서버 플러그인을 업데이트하고 재시작하세요.
- Termux용 am이 없으면 pkg install termux-am을 실행하세요.
- 앱 응답이 없으면 앱을 한 번 열고 다시 확인하세요. 진단 내용이 확장 설정에 표시됩니다.
- 서버가 PC에 있으면 휴대폰에 설치한 앱을 이 방식으로 호출할 수 없습니다.
- 프로세스 종료나 휴대폰의 절전 정책 등 실제 기기 환경은 별도 확인이 필요합니다.

## 동작과 개인정보

서버가 표시가 붙은 메인 생성 응답의 종료를 감지해 명시적 브로드캐스트로 앱을 호출합니다.
다른 앱을 볼 때만, 소리, 진동을 설정할 수 있습니다.
숨은 생성(quiet)과 impersonate는 제외하고 동일 요청의 중복 알림을 막습니다.
알림 본문은 고정 완료 문구이며, 알림을 누르면 생성 당시 실리태번 주소를 브라우저로 엽니다.
서버와 브라우저가 종료돼 있으면 새로운 생성 완료 알림은 만들 수 없습니다.

Android 앱은 알림 권한만 요청합니다. 인터넷·파일·사진·연락처·문자·접근성 권한과 상시 실행 서비스가 없습니다.
외부 푸시 서버나 추가 AI API 크레딧을 사용하지 않습니다.
