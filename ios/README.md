# Silly-Pop iOS

**1.0.0 · 정식 배포 · iOS/iPadOS 16.4 이상**

실리 답장을 기다리면서 다른 앱을 보고 싶을 때 쓰는 아이폰 알림 앱입니다. Safari에서 홈 화면에 추가하는 웹앱이라 APK나 App Store 설치는 필요하지 않아요. 채팅은 원래 쓰던 실리 웹앱에서 그대로 하면 됩니다.

- [아이폰 알림 앱 열기](https://foreverharibo-boop.github.io/Silly-Pop/)
- [Silly Relay 설치 안내](https://github.com/foreverharibo-boop/Silly-Relay)
- [갤럭시용 Silly-Pop](https://github.com/foreverharibo-boop/Silly-Pop/tree/main)

갤럭시용 앱과 별개로 설치합니다. 아이폰 알림에 갤럭시용 APK는 필요하지 않습니다. 서버가 갤럭시 Termux에 있어도, PC에 있어도 그 서버에 아이폰으로 접속하는 구성입니다. 직접 확인한 환경은 **갤럭시 Termux 서버 + 아이폰 12 홈 화면 웹앱**입니다.

## 작동 방식

실리에서 일반 답장·재생성·스와이프로 새 답장을 요청하면, 서버가 응답 수신을 마쳤을 때 Apple 웹 푸시로 **“답장이 도착했어요”**를 보냅니다. 기존 스와이프 후보를 넘겨 보기만 할 때는 보내지 않습니다. 번역·검수의 완료 알림은 아닙니다.

**Silly Relay를 함께 켜면** 브라우저가 멈추거나 페이지가 다시 열려도 서버가 이미 접수한 생성을 계속 받고, 원래 채팅으로 돌아왔을 때 지원되는 답장을 복구합니다. 실리태번 서버 자체는 계속 켜져 있어야 합니다.

알림을 누르면 Silly-Pop iOS가 열립니다. 사용하던 실리 웹앱으로 바로 돌아가는 기능은 없습니다. 알림에는 대화 내용이나 캐릭터 이름을 넣지 않습니다.

## 사용 조건

- iOS/iPadOS 16.4 이상에서 Safari로 알림 앱을 **홈 화면에 추가**하고 알림을 허용해 주세요. iPhone 7의 iOS 15에서는 이 알림 앱을 사용할 수 없습니다.
- 실리태번 서버에 Node.js 18 이상, Git, npm과 서버 플러그인 사용 설정이 필요합니다.
- 실리태번 서버와 아이폰 모두 인터넷에 연결되어 있어야 합니다. 아이폰에서 실리에 접속하던 Tailscale 등 연결 방법은 그대로 사용합니다.
- 백그라운드 생성·복구를 위해 **Silly Relay 서버 플러그인과 확장**도 설치하고 켜 주세요. [설치 안내](https://github.com/foreverharibo-boop/Silly-Relay)
- 현재 실제 테스트는 제작자의 개인 환경과 확장 조합에서 진행했습니다. 다른 기기·서버·확장 조합까지 모두 확인한 것은 아닙니다.

## 1. 서버에 설치

진행 중이거나 복구를 기다리는 답장을 먼저 받은 다음 서버를 종료하세요. **서버가 있는 기기**에서 실행합니다. 아래는 Termux의 `~/SillyTavern` 기준입니다.

```bash
git clone --branch ios --single-branch https://github.com/foreverharibo-boop/Silly-Pop.git ~/Silly-Pop-iOS
node ~/Silly-Pop-iOS/ios/install.cjs ~/SillyTavern
```

첫 명령이 성공한 다음 두 번째 명령을 실행해 주세요. 서버 플러그인과 웹 확장을 함께 설치하므로, 같은 저장소를 실리의 확장 설치 칸에 별도로 넣지 않습니다.

- 실리 폴더 이름이 `TavernAI`라면 마지막 인수만 `~/TavernAI`로 바꿉니다. 이름만 옛 이름인 **SillyTavern 설치 폴더**여야 하며 실제 구형 TavernAI는 지원하지 않습니다.
- `default-user` 이외 계정은 마지막에 사용자 폴더 이름을 붙입니다: `node ~/Silly-Pop-iOS/ios/install.cjs ~/SillyTavern 계정이름`
- 실제 사용하는 `config.yaml`의 기존 `enableServerPlugins`가 `true`여야 합니다. 이미 릴레이 등 서버 플러그인이 작동한다면 그대로 두세요.
- 설치기는 이 앱의 서버 플러그인과 확장만 설치합니다. 채팅·캐릭터·config.yaml·갤럭시용 실리팝·릴레이는 수정하지 않습니다. 동명의 다른 폴더나 심볼릭 링크는 덮어쓰지 않습니다.

평소 방법으로 서버를 켜고 `[Silly-Pop iOS] 1.0.0 loaded`를 확인한 다음, 아이폰의 **실리 페이지도 새로고침**해 주세요.

### PC 서버 / 다른 데이터 경로

PC에서도 위 저장소의 `ios` 브랜치를 받은 뒤, Node.js로 `ios/install.cjs`에 **실제 실리태번 폴더의 절대 경로**를 넘깁니다. 경로에 공백이 있다면 따옴표로 감싸 주세요.

```text
node "Silly-Pop-iOS/ios/install.cjs" "C:/실제경로/SillyTavern"
```

별도로 지정한 data 디렉터리는 자동 설치 대상이 아닙니다. `ios/extension` 내용과 `ios/LICENSE`를 실제 사용자의 `extensions/Silly-Pop-iOS`에, `ios/server`, `ios/package.json`, `ios/package-lock.json`, `ios/LICENSE`를 `plugins/Silly-Pop-iOS`에 복사하고 플러그인 폴더에서 `npm ci --omit=dev --ignore-scripts`를 실행합니다. 기존 설치가 있다면 먼저 해당 폴더를 백업하세요.

## 2. 아이폰에서 연결

1. [알림 앱 주소](https://foreverharibo-boop.github.io/Silly-Pop/)를 **Safari**에서 열고 **공유 → 홈 화면에 추가**합니다. 추가한 **Silly-Pop iOS 아이콘**으로 다시 열어 주세요.
2. 원래 쓰던 실리 웹앱의 확장 설정 → **Silly-Pop iOS → 아이폰 처음 연결하기 → 연결 코드 만들기**를 누릅니다.
3. 코드를 실리팝 앱에 붙여 넣고 **연결 코드 확인 → 알림 허용하기**를 누릅니다.
4. 나온 **완료 코드**를 복사해 실리의 **아이폰 연결 완료** 칸에 붙여 넣고 완료합니다. 코드는 10분 동안 유효합니다.
5. 실리에서 **테스트 알림**을 누르고 아이폰에 팝업이 실제로 오는지 확인합니다.
6. **Silly Relay → 연결 유지**, **Silly-Pop iOS → 이 브라우저에서 보낸 답장 알림**을 켭니다. 메시지를 보낸 뒤 서버 접수·복구 준비 표시를 확인하고 홈 화면으로 나가 보세요.

처음 연결할 때 한 번만 코드를 주고받으면 됩니다. 평소에는 알림 앱을 계속 열어 둘 필요 없이 기존 실리에서 채팅하세요.

## 업데이트

서버를 재시작하면 릴레이가 아직 전달하지 못한 임시 답장이 사라집니다. 진행 중이거나 복구할 답장을 먼저 받은 뒤 서버를 종료해 주세요.

정식 버전으로 처음 설치했다면:

```bash
git -C ~/Silly-Pop-iOS pull --ff-only
node ~/Silly-Pop-iOS/ios/install.cjs ~/SillyTavern
```

**시험판을 설치했던 분은 폴더를 지우거나 새로 연결하지 말고**, 기존 폴더에서 다음을 실행하면 됩니다. `ios-preview`는 기존 설치자의 업데이트 호환 경로로 같은 정식 버전을 제공합니다.

```bash
git -C ~/Silly-Pop-iOS-preview pull --ff-only
node ~/Silly-Pop-iOS-preview/ios/install.cjs ~/SillyTavern
```

서버를 다시 켜고 실리 페이지를 새로고침합니다. 알림 앱도 인터넷이 연결된 상태에서 다시 열어 주세요. 앱 주소·구독·연결 키·설정 저장 이름을 유지하므로 이 업데이트 때문에 앱을 삭제하거나 재연결할 필요는 없습니다. 기존 홈 화면 아이콘 이름은 iOS가 바로 갱신하지 않을 수 있습니다.

이 앱의 서버 플러그인과 확장은 **위 명령으로 함께 업데이트**합니다. 설치기는 이전 버전 파일을 실리 폴더의 `.silly-pop-ios-backups`에 보관합니다. 릴레이의 업데이트 방법은 릴레이 안내를 따릅니다.

## 알림이 오지 않을 때

- 아이폰 설정의 알림 권한·집중 모드·네트워크와 실리 서버 실행 상태를 확인해 주세요. 소리·진동은 iOS 설정을 따릅니다.
- **다른 화면을 볼 때만**은 서버에 마지막으로 전달된 화면 상태를 따릅니다. iOS가 상태 전송 전에 웹앱을 강제 종료하면 실제 상태와 다를 수 있어요. 먼저 이 옵션을 끄고 테스트 알림과 실제 답장 알림을 비교해 주세요.
- 앱 삭제·사이트 데이터 초기화로 구독이 없어졌다면 다시 연결합니다. 단순 업데이트에는 재연결하지 않습니다.
- 그룹·숨은 생성·도구만 호출한 응답·API 오류는 지원 대상이 아니며 다른 확장이 별도 생성 경로를 쓰는 경우 호환되지 않을 수 있습니다. 2 MiB보다 큰 응답은 알림을 생략하고 답장 전달은 계속합니다.
- 알림만 끄려면 해당 실리 브라우저에서 알림 스위치를 끕니다. 기기 연결 해제는 실리의 **선택 기기 해제**와 알림 앱의 **이 기기 알림 구독 해제**를 사용합니다.

오류가 생기면 배포글의 문의 달글 또는 본문 댓글로 알려 주세요. 기기·iOS 버전·실리 서버 환경·오류 문구를 함께 적어 주시면 확인에 도움이 됩니다. 연결 코드, 완료 코드, API 키는 올리지 말아 주세요.

## 개인정보와 비용

- 알림 기능은 AI API를 호출하지 않습니다. 평소 실리 답장 생성에 드는 API 사용료는 그대로입니다.
- 대화 내용·캐릭터명·AI API 키를 푸시에 넣지 않습니다. 알림 전송에는 Apple 푸시 서비스, 앱 파일 제공에는 GitHub Pages를 사용합니다.
- 서버의 발송용 비밀키와 기기 구독은 서버의 `~/.config/silly-pop-ios/push.json`에 저장합니다. 디렉터리 권한은 700, 파일 권한은 600입니다. **이 파일과 연결/완료 코드를 공개하지 마세요.** 설치 주소는 공유해도 됩니다.
- 연결 코드는 10분 뒤 만료되며 한 번만 사용합니다. 기기는 실리 사용자 계정별로 분리하고 실리의 기존 인증·CSRF 보호 아래에서 처리합니다. 같은 계정을 공동 사용하면 그 계정 안의 사용자를 따로 구분하지 않습니다.
- 보안 관련 자동 검사를 진행했지만 전문 보안 감사를 받은 제품은 아닙니다.

## 검증·라이선스

정식 배포 전 제작자가 아이폰에서 실제 알림 수신과 릴레이 복구 테스트를 진행하고 정상 작동을 확인했습니다. 서버·기기 조합 전체를 보증하는 의미는 아닙니다. 이번 정식 전환은 시험을 마친 생성·복구·푸시 로직을 유지하고 버전, 표시 이름, 설치·배포 안내를 정리한 릴리스입니다.

```bash
npm ci --prefix ios --ignore-scripts
npm test --prefix ios
node ios/tests/relay.integration.cjs /실제경로/Silly-Relay
```

자동 검사는 연결 만료·재사용·계정 분리, 전송 주소 제한, 오류 격리, JSON/SSE 전달, 릴레이 처리 순서와 접수 재시도, 중복 AI 호출 방지를 확인합니다. AI·Apple 전송을 모의 처리하므로 자동 검사 자체는 AI 비용이 들지 않습니다.
