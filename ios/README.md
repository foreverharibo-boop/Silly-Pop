# Silly-Pop iOS · 알림 시험판

**0.1.0-test.1 · iOS/iPadOS 16.4 이상 · 홈 화면에 추가하는 알림 앱**

갤럭시 실리팝과 독립된 시험판입니다. 현재 갤럭시 APK와 실리팝 배포본은 바꾸지 않습니다. Silly Relay도 기존 버전을 그대로 사용합니다. 릴레이는 갤럭시와 아이폰 모두에서 사용할 수 있습니다.

## 어떻게 작동하나요?

1. 실리는 지금 쓰는 HTTP/Tailscale 주소로 접속합니다.
2. 아이폰에는 별도의 HTTPS Silly-Pop 웹앱을 홈 화면에 추가합니다.
3. 처음 한 번 연결 코드를 서로 복사해 연결합니다. 알림 앱은 HTTP 실리 서버에 직접 접속하지 않습니다.
4. 실리에서 답장을 요청하면 서버 플러그인이 응답 수신 완료를 확인하고 Apple 웹 푸시로 알립니다. 아이폰이 다른 화면에 있어도 알림을 받을 수 있습니다. 실제 수신은 iOS 권한·집중 모드·네트워크 상태에 영향을 받습니다.
5. 알림에는 **“답장이 도착했어요”**만 표시합니다. 누르면 알림 앱이 열립니다. 기존 실리 웹앱을 자동으로 여는 기능은 없습니다.

**Silly Relay를 함께 켜야 브라우저가 멈추거나 새로고침돼도 서버 수신이 계속됩니다.** 이 앱은 알림 역할을 맡고, 연결 유지·답장 복구는 릴레이가 맡습니다. 번역·검수의 완료 알림은 아닙니다.

## HTTPS 앱 주소 준비 (제작자가 한 번)

GitHub 저장소 Settings → Pages → Build and deployment에서 **Deploy from a branch**, **ios-preview**, **/docs**를 선택하고 Save 합니다. 준비가 끝나면 아래 주소가 열립니다.

https://foreverharibo-boop.github.io/Silly-Pop/

Pages 설정 전에는 이 주소를 사용할 수 없습니다. 앱 코드와 아이콘만 공개되며, 서버 연결 키·대화·기기 등록 정보는 GitHub에 올라가지 않습니다. 다른 곳에 호스팅한다면 `docs` 안의 파일만 HTTPS로 올리고 확장 `index.js`의 PWA 주소를 바꿉니다. 동일 주소를 계속 사용해야 기존 아이폰 알림 구독이 유지됩니다.

## Termux 서버에 설치

실리 서버를 종료한 뒤 **새 Termux 셸**에서 실행하세요. 경로가 `~/SillyTavern`인 경우입니다.

```bash
git clone --branch ios-preview --single-branch https://github.com/foreverharibo-boop/Silly-Pop.git ~/Silly-Pop-iOS-preview
node ~/Silly-Pop-iOS-preview/ios/install.cjs ~/SillyTavern
```

- `~/TavernAI`에 설치했다면 두 번째 명령 마지막 인수를 `~/TavernAI`로 바꿉니다. 이름만 옛 이름인 **SillyTavern 설치 폴더**여야 합니다. 실제 구형 TavernAI는 지원하지 않습니다.
- `default-user` 이외 계정은 마지막에 실제 사용자 폴더 이름을 추가합니다: `node .../ios/install.cjs ~/SillyTavern 계정이름`
- 커스텀 data 디렉터리는 자동 설치 대상이 아닙니다. `ios/extension` 내용을 실제 사용자 extensions/Silly-Pop-iOS에, `ios/server`, `ios/package.json`, `ios/package-lock.json`을 plugins/Silly-Pop-iOS에 복사하고 그 플러그인 폴더에서 `npm ci --omit=dev --ignore-scripts`를 실행합니다.
- 설치기는 이 시험판의 서버 플러그인과 확장만 설치합니다. 채팅·캐릭터·config.yaml·기존 실리팝·릴레이는 수정하지 않습니다. 동명의 알 수 없는 폴더나 심볼릭 링크는 덮어쓰지 않습니다.
- 기존 `enableServerPlugins: true` 설정이 필요합니다. 이미 릴레이가 작동한다면 그대로 두세요.

평소 방법으로 서버를 다시 켭니다. `[Silly-Pop iOS] 0.1.0-test.1 loaded`가 표시되면 준비됐습니다. **실리 페이지도 새로고침**하세요.

## 아이폰에서 한 번만 연결

1. 위 HTTPS 앱 주소를 Safari에서 열고 **공유 → 홈 화면에 추가**합니다. 추가한 **Silly-Pop 아이콘으로 다시 열어야** 알림을 허용할 수 있습니다.
2. 기존 실리 웹앱의 확장 설정 → **Silly-Pop iOS → 아이폰 처음 연결하기 → 연결 코드 만들기**를 누릅니다.
3. 코드를 복사해 Silly-Pop 앱의 첫 번째 칸에 붙여 넣고 **연결 코드 확인 → 알림 허용하기**를 누릅니다.
4. 나온 **완료 코드**를 복사해 기존 실리의 **아이폰 연결 완료** 칸에 붙여 넣고 완료합니다. 코드는 10분 동안만 유효합니다.
5. 실리에서 **테스트 알림**을 누릅니다. Apple 접수 문구만 보지 말고 아이폰에 팝업이 실제로 오는지 확인하세요.
6. 기존 실리 웹앱에서 **Silly Relay 켜기**, **Silly-Pop iOS의 이 브라우저에서 보낸 답장 알림 켜기**를 확인합니다. 메시지를 한 번 보내고 홈 화면으로 나가 알림을 확인합니다.

이 두 번의 확인(테스트 알림, 실제 답장 알림)이 첫 실기기 검사입니다. 로컬 자동 검사는 완료할 수 있지만 **Apple 실서버와 사용자 아이폰의 수신까지 개발 환경에서 확인할 수는 없습니다.**

## 지원 범위와 제한

- 일반 Chat Completion 답장·재생성·스와이프에 알림을 붙입니다. 숨은 생성, 사용자 대필, 도구만 호출한 응답, API 오류 응답은 제외합니다. 다른 확장이 별도 생성 경로를 쓰는 경우 아직 지원하지 않을 수 있습니다.
- 서버 알림 판단은 응답 본문 최대 2MiB 이내에서 처리합니다. 그보다 큰 응답은 알림을 생략하고 답장 전달은 계속합니다.
- **다른 화면을 볼 때만**은 해당 실리 브라우저가 서버에 보낸 마지막 화면 상태를 따릅니다. iOS가 상태 전송 직전에 페이지를 강제 종료하면 실제 화면 상태와 달라 알림이 누락될 수 있습니다. 먼저 이 옵션을 끄고 알림 자체를 시험할 수 있습니다.
- 소리·진동·집중 모드는 iOS 설정을 따릅니다. 앱에서 강제로 소리나 진동을 켜지 않습니다.
- 답장 내용·캐릭터명·AI API 키를 푸시로 보내지 않습니다. 서버와 Apple 사이에 알림 제목, 수신 구독 주소 및 암호화 정보가 오갑니다. 앱 파일 다운로드에는 GitHub Pages가 사용됩니다.
- 개인 서버의 VAPID 비밀키와 기기 구독은 서버의 `~/.config/silly-pop-ios/push.json`에 저장합니다. 디렉터리 700, 파일 600 권한입니다. 연결/완료 코드는 다른 사람에게 공유하지 마세요. AI 키를 입력할 곳은 없습니다.
- 기기 목록은 실리 사용자 계정별로 분리합니다. API는 실리의 기존 로그인·CSRF 보호 아래에서 동작합니다. 로그인 없이 한 계정을 공동 사용하는 사람들 사이의 별도 권한 분리는 하지 않습니다.
- 아이폰 앱 삭제·사이트 데이터 초기화 후에는 다시 연결해야 합니다. 만료된 구독은 Apple의 404/410 응답 때 서버에서 제거합니다. 알림 전송은 AI를 재호출하지 않습니다.
- iPhone 7 / iOS 15에는 웹 푸시가 없어 이 앱의 알림 시험이 불가능합니다. iOS 16.4 이상 홈 화면 앱이 필요합니다.

## 업데이트 / 끄기

서버를 종료하고 아래를 실행한 뒤 다시 시작합니다. 이 시험판은 실리의 확장 업데이트 버튼 대신 아래 명령으로 함께 업데이트합니다.

```bash
git -C ~/Silly-Pop-iOS-preview pull --ff-only
node ~/Silly-Pop-iOS-preview/ios/install.cjs ~/SillyTavern
```

이전 시험판 코드는 실리 설치 폴더 `.silly-pop-ios-backups`에 남깁니다. 키·구독은 설치 폴더 밖에 유지됩니다.

알림만 멈추려면 해당 브라우저에서 알림 스위치를 끕니다. 기기 연결을 없애려면 실리의 **선택 기기 해제**, 아이폰 앱의 **이 기기 알림 구독 해제**를 사용합니다. 릴레이는 계속 사용할 수 있습니다.

## 개발 확인

```bash
npm ci --prefix ios --ignore-scripts
npm test --prefix ios
```

연결 코드의 계정 분리·만료·재사용 거부, 푸시 주소 제한, 권한, 기기 해제, 중복 방지, 화면 상태, 실패 격리, JSON/SSE 응답 보존과 기존 릴레이 앞뒤에서의 요청 표시를 검사합니다. 기존 Android 소스와 기존 실리팝 파일은 수정하지 않습니다.

AGPL-3.0-or-later. 기존 저장소 LICENSE 적용. Web Push 구현은 `web-push`(MIT)를 사용합니다.

릴레이와 합친 요청 흐름도 로컬에서 확인할 수 있습니다(실제 AI·Apple 전송 없음).

```bash
node ios/tests/relay.integration.cjs /실제경로/Silly-Relay
```

두 확장의 요청 처리 순서가 바뀌거나 서버 접수 확인 응답이 유실되어도, AI 요청과 알림 대상이 중복되지 않는지 검사합니다. 브라우저가 응답을 읽지 않아도 서버 완료가 알림 처리로 이어지는지도 검사합니다. 로컬 브라우저에서는 모바일 배치·연결 코드 입력·알림 권한 흐름(구독 모의 처리)·실제 서비스 워커 설치와 오프라인 화면을 확인했습니다. Apple 푸시 실수신 검사는 여전히 별도입니다.
