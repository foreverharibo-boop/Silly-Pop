# PC → 갤럭시 푸시 (배포 전 개발 버전)

기존 APK에 FCM 수신 기능을 추가합니다. 상시 알림·포그라운드 서비스·지속 연결은 만들지 않습니다. 앱을 열어 두지 않아도 Google Play 서비스가 푸시를 전달하고, 앱은 도착한 답장 알림만 표시합니다. 기존 Termux 서명 브로드캐스트는 그대로 사용할 수 있습니다.

현재 `remote-config.json`의 주소가 비어 있으며 Firebase 설정도 없습니다. **코드와 개발용 APK만으로 실제 원격 푸시를 받을 수 있는 상태가 아닙니다.** 운영 서버 연결, 서명된 APK, 실제 갤럭시 수신 검증 후 배포해야 합니다. iOS 푸시 서버와는 별개입니다.

## 이용자 흐름 (설정된 정식 APK 배포 후)

1. PC의 SillyTavern에 Silly-Pop 서버 플러그인과 웹 확장을 설치합니다. 화면을 떠나도 생성을 이어가려면 Silly Relay도 필요합니다.
2. 갤럭시에 업데이트된 Silly-Pop APK를 설치하고 알림을 허용합니다.
3. 앱의 **PC 연결 코드 복사**를 누릅니다.
4. PC 서버에 접속한 실리태번의 Silly-Pop → **컴퓨터 서버 → 갤럭시 연결**에 붙여넣고 **폰 연결**을 누릅니다. 코드는 10분 동안 한 번만 사용할 수 있습니다.
5. **테스트 알림 보내기**로 실제 폰 수신을 확인합니다. 이후 서버에 답변이 도착하면 알림이 옵니다. 화면을 보고 있을 때도 받고 싶으면 기존 **다른 앱을 볼 때만** 옵션을 끕니다.

사용자는 Firebase 계정을 만들지 않습니다. 하나의 폰에는 PC의 실리태번 계정 하나를 연결하며, 다시 연결하면 이전 PC 연결은 폐기됩니다. 연결은 실리태번 계정별로 저장됩니다. PC 연결이 있으면 해당 계정은 로컬 Termux 대신 원격 푸시를 사용합니다. **PC 연결 해제**로 Termux 경로로 돌아갈 수 있습니다.

알림 제목은 고정된 “답장이 도착했어요”입니다. 알림을 누르면 기존에 연결된 웹앱이 있으면 열고, 없으면 Silly-Pop 설정 화면을 엽니다. 원격 PC 주소는 푸시 서버로 보내지 않으므로 자동으로 주소를 찾지는 않습니다.

## 운영자가 한 번 설정할 것

1. 전용 Firebase 프로젝트를 만듭니다. Android 앱 패키지명은 `com.foreverharibo.sillypop`입니다. Analytics는 필요 없습니다.
2. Firebase Authentication의 **익명 로그인**을 켭니다. 이용자 로그인 화면은 없으며 기기 등록 권한 확인에만 사용합니다.
3. Firestore를 만들고 이 디렉터리의 `firestore.rules`를 배포합니다. 클라이언트 직접 읽기·쓰기는 전부 거부하고 Cloud Functions의 Admin SDK만 사용합니다. 기존 다른 앱 프로젝트의 규칙을 덮어쓰지 않도록 전용 프로젝트를 사용하세요.
4. Cloud Functions 배포에 필요한 결제 요금제와 예산 알림, 공개 엔드포인트 호출 제한을 설정합니다. FCM 자체와 별개로 Functions/Firestore 비용이 생길 수 있습니다. 이 변경에서는 프로젝트·유료 자원·서버를 생성하거나 배포하지 않았습니다.
5. 관리자 환경에서 `npm ci --prefix functions` 후 Firebase CLI로 이 디렉터리에서 `firebase deploy --only functions,firestore:rules --project PROJECT_ID`를 실행합니다. Functions 런타임의 기본 서비스 계정 권한을 사용합니다. **서비스 계정 개인 키를 APK, PC 플러그인, 공개 저장소에 넣지 마세요.**
6. 배포된 `push` 함수 HTTPS URL을 저장소 루트 `remote-config.json`의 `gatewayUrl`에 넣습니다. APK와 PC 플러그인은 반드시 같은 주소를 사용해야 합니다. 사용자가 제공한 코드에서 임의 URL을 읽지 않습니다.
7. Firebase에서 받은 `google-services.json`을 `android-app/app/google-services.json`에 넣습니다. 이 파일은 Git에서 제외됩니다. 이 파일과 주소가 모두 있어야 APK의 PC 연결 버튼이 활성화됩니다.
8. `android-app`에서 `gradle :app:assembleRelease`를 기존과 같은 앱 서명 키로 빌드합니다. GitHub 배포 시 `SILLY_POP_GOOGLE_SERVICES_JSON` 저장소 secret에 파일 내용을 등록합니다. 정식 배포 워크플로는 main에서 `publish`를 명시적으로 켜서 실행할 때만 새 v1.1.0을 배포합니다. 기존 앱 업데이트 설치를 위해 서명 키가 같아야 합니다. 개발용 debug APK는 기존 정식 앱 위에 설치할 수 없습니다.
9. Firestore `pairs` 컬렉션의 `expiresAt` 필드에 TTL 삭제를 켭니다. 실제 만료 판단은 서버 시각으로 즉시 수행하며 TTL 삭제 시점에 의존하지 않습니다. 익명 사용자/연결 해제 기기 기록 정리, 엔드포인트 남용 감시도 운영 전에 설정하세요.

## 검증과 한계

- `npm test` (루트): 기존 생성 알림 회귀 테스트, 계정 구분, 일회용 연결 코드, 동시 등록, 토큰 갱신, 연결 해제, 중복/빈도 제한, 민감 정보 전송 방지.
- `gradle :app:connectedDebugAndroidTest`: 실제 Android 알림 권한·로컬 브로드캐스트·아이콘, 원격 메시지 표시, 중복 억제, 상시/포그라운드 알림 플래그 부재.
- `.github/workflows/remote-preview.yml`: 테스트·APK 컴파일·lint·에뮬레이터 확인용입니다. GitHub Release나 기존 APK를 덮어쓰지 않습니다. Firebase 미설정 APK는 원격 푸시 실사용용이 아닙니다.
- 실제 Google FCM 전송, 다른 네트워크의 PC→폰, 화면 잠금/앱 화면 종료, 네트워크 복구, 토큰 교체 후 수신은 설정된 빌드와 실제 기기로 검증해야 합니다. 자동 테스트는 이를 대신하지 않습니다.
- 앱 **강제 종료**, 알림 권한 차단, Google Play 서비스 부재, 네트워크/기기 전원 관리에 따라 알림이 지연되거나 오지 않을 수 있습니다. “항상 즉시”를 보장하지 않습니다.
- PC나 SillyTavern 서버가 꺼지면 새 답장을 받아 알림을 보낼 수 없습니다. 이 기능은 AI 생성을 유지하거나 답장을 복구하지 않습니다. 그것은 Silly Relay의 역할입니다.
- FCM 접수 성공은 폰 수신 확인이 아닙니다. 오류 후 같은 요청 ID는 자동 재전송하지 않아 중복 알림을 막습니다. 한 연결당 2초 간격/시간당 120개 제한, 5분 전달 유효 시간을 적용합니다.
- 운영 전 프로젝트 수준의 남용 방어/비용 모니터링을 구성해야 합니다. 앱별 인증과 전송 빈도 제한만으로 공개 서버 호출 비용까지 제한되지는 않습니다.

## 데이터

Google 인증/푸시 서비스와 운영자 서버는 익명 기기 식별자, FCM 토큰, 일회용 연결 코드의 해시, PC 전송 권한 해시, 전송 시각·요청 ID·소리/진동 설정을 처리합니다. 대화 본문·캐릭터 이름·AI API 키·실리태번 주소는 보내지 않습니다. PC 전송 권한은 서버 사용자 홈의 `.config/silly-pop/remote/`에 계정별 0600 파일로 저장됩니다 (Windows는 OS 계정 폴더 ACL 사용). 폰의 **PC 알림 연결 해제**는 기기 토큰/연결 정보를 서버에서 제거하고 이후 수신 표시도 끕니다.
